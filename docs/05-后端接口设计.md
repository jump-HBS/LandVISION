# 05 后端接口设计（v1.2）

> 基础地址：`http://127.0.0.1:8000/api`，交互式文档：`/docs`（Swagger UI）。
> 所有地图数据返回 GeoJSON；所有错误统一返回 `{code, message, detail}`。

## 1. 统一约定

### 1.1 错误格式（全局异常处理器）

| 状态码 | code | 说明 |
|---|---|---|
| 400/422 | INVALID_PARAMS / VALIDATION_ERROR | 参数错误 |
| 401/403 | UNAUTHORIZED / FORBIDDEN | 认证鉴权（预留） |
| 404 | NOT_FOUND | 资源不存在 |
| 409 | CONFLICT | 业务冲突（如地块编号重复） |
| 429 | RATE_LIMITED | 触发限流 |
| 501 | NOT_IMPLEMENTED | 功能未实现 |
| 500 | INTERNAL_ERROR | 服务器内部错误 |

### 1.2 分页格式（列表接口）

请求：`?page=1&page_size=20`（page_size 最大 100）
响应：`{"items": [...], "total": 10, "page": 1, "page_size": 20, "pages": 1}`

### 1.3 安全与运维

- 安全响应头 / X-Request-ID / 限流（120 次/分）/ 审计（`/api/system/audit`）
- 健康检查 `GET /healthz`；服务信息 `GET /api/system/info`

## 2. parcels 地块（`/api/parcels`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/parcels` | 分页列表；`?bbox=` `?land_use=`（12 大类） `?district=` `?region_code=` `?q=` |
| GET | `/parcels/geojson` | FeatureCollection；支持 `bbox` |
| GET | `/parcels/{id}` | 详情 |
| POST | `/parcels` | 新建；用地性质做 12 大类枚举校验；编号重复 409 |
| PUT | `/parcels/{id}` | 更新 |
| DELETE | `/parcels/{id}` | 删除 |
| POST | `/parcels/import-shp` | **SHP 批量导入**（multipart：file + name_field/land_use_field/region_field/region_code） |

SHP 导入说明：上传 zip（.shp/.shx/.dbf/.prj）；仅接受 WGS84/EPSG:4326（投影坐标系请先用 GDAL 转换）；属性字段可自动识别或手动指定；地类字段容错映射到 12 大类；返回 `{imported, skipped, fields, has_prj}`。

## 3. regions 行政区划（`/api/regions`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/regions` | 分页列表；`?level=country/province/city/county&parent_code=` |
| GET | `/regions/geojson` | GeoJSON；无 code 返回全部省级，有 code 返回其直接下级 |
| GET | `/regions/{code}` | 详情（100000=中国虚拟根节点） |
| GET | `/regions/{code}/children` | 直接下级列表（100000 → 省级） |
| GET | `/regions/{code}/locate` | 定位：`{code,name,level,center,bbox}`（市级无几何时由县域推导 bbox） |
| POST | `/regions/import` | 市/县级 SHP 导入（multipart：file + level + parent_code + code_field + name_field） |

> v1.3：国家-省-市-县四级检索。省级 34 个内置；市级 348 + 县域 2891
> 由 `中国_县.geojson` 转换（`tools/build_regions.py`），
> Demo 模式懒加载 `backend/app/data/china_regions.json`；
> PostgreSQL 入库执行 `tools/load_regions_pg.py <用户> <密码>`。

## 5. planning 规划审查 · 三区三线合规性体检（`/api/planning`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/planning/zones` | 审查地块（规划控制要素）列表 |
| GET | `/planning/zones/geojson` | 审查地块 GeoJSON |
| POST | `/planning/zones` | 新增审查地块（类型：永久基本农田/生态保护红线/城镇开发边界/其他） |
| DELETE | `/planning/zones/{id}` | 删除审查地块 |
| POST | `/planning/zones/import-shp` | SHP 批量导入审查地块（类型字段自动容错映射） |
| GET | `/planning/check/{parcel_id}` | 单地块符合性检查 |
| POST | `/planning/check` | 任意 GeoJSON 几何检查 |
| POST | `/planning/review` | **批量体检**：`{scope, zone_ids, parcel_ids}` → 范围内地块占用各类型审查地块面积（rows + totals） |
| POST | `/planning/review/export` | **问题台账 CSV 导出**：同 review 请求体 → 带 BOM 的 UTF-8 CSV（Excel 直接打开） |

> v1.3：模块四升级为“三区三线合规性批量体检”：审查范围支持 当前行政区 / SHP 导入 / 手动划定；
> 结果输出问题台账（地块 × 审查要素占用矩阵，动态列支持自定义“其他”类型）并支持 CSV 导出；
> 结论规则：占用永久基本农田/生态保护红线 → 冲突，其余重叠 → 提示。

## 6. analysis 空间分析（`/api/analysis`，模块一~三）

### 6.1 模块一 · 用地变化转移矩阵（`/analysis/transition`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/transition/import-shp` | 导入期次地块（multipart：file + `period`=base/current + name_field/land_use_field/region_code） |
| POST | `/transition/generate-demo-base` | 一键生成演示基期（模拟 1 转换 + 1 边界调整 + 1 新增；重复调用自动跳过） |
| POST | `/transition/matrix` | 计算转移矩阵：`{scope}` → rows（from_use/to_use/area_sqm，含消失/新增虚拟地类）、summary（各地类面积增减）、changes_geojson |

### 6.2 模块二 · 土地适宜性评价（`/analysis/suitability`）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/suitability/targets` | 评价目标与默认因子权重（建设用地适宜性 / 耕地适宜性） |
| POST | `/suitability/evaluate` | 多因子加权叠加评价：`{target, weights, scope}` → 40×40 格网 cells_geojson（score/level）+ stats |

> 因子得分 0~100；权重自动归一化；分级：≥80 高度适宜 / 60~80 中等适宜 / 40~60 勉强适宜 / ＜40 不适宜。
> 建设用地因子：交通便利度/公共服务配套/生态约束(负向)/现状建成邻近；耕地因子：水源邻近度/地形平缓度(模拟)/耕作服务便利/生态约束(负向)。

### 6.3 模块三 · 服务设施可达性分析（`/analysis/accessibility`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/accessibility/analyze` | 可达性分析：`{facility_types, radius_m, scope}` → 覆盖率 / 盲区清单 gaps / parcels_geojson（covered + nearby） |

> 判定：地块质心到所选 POI 直线距离 ≤ 服务半径（默认 800m，15 分钟生活圈口径）即覆盖；facility_types 为空 = 全部设施。

### 6.4 通用 · SHP 范围解析（`/analysis/parse-scope`）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/parse-scope` | 解析 SHP 压缩包为分析范围几何（不落库，取全部要素并集）：`{feature_count, scope, bbox}` |

## 7. dashboard 数据驾驶舱（`/api/dashboard`，统筹汇总）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/dashboard/summary` | 按分析范围聚合全模块统计：`{scope, scope_label}` → 地块/用地结构/行政区分布/转移矩阵/三区三线体检/设施可达性（与报告生成同源，保证两模块数据一致） |

> 驾驶舱下钻选择省/市/县任意层级，前端取 `/regions/{code}` 边界作为 scope。
